Speculative Decoding 的朴素思想

想要加速一个 auto-regressive 模型的推理, 可以先猜测合理的上下文, 再让大模型一次验证多个位置; 比如已经有 prefix, 小模型先猜出 I love cats, 大模型验证后保留 I love, 在 cats 这里拒绝并补出 dogs, 后面基于 cats 生成的内容就不能继续保留;

这里有两个角色: Draft Model 负责快速生成候选, Target Model 负责验证和确定最终输出; 上面的例子是在说明接受前缀和截断的位置, 随机 sampling 下的接受规则还需要下面的概率推导;

本文主要根据四页手稿整理, 保留从 sampling 理论到 SpecInfer, Medusa, EAGLE-1 的顺序; 图片选用原论文架构图, 对手稿中公式或表述的必要修正单独说明;

理论部分对应 Google 的 Fast Inference from Transformers via Speculative Decoding 和 DeepMind 的 Accelerating Large Language Model Decoding with Speculative Sampling; 两篇独立提出了相近的机制; 本文统一用 ppp 表示 target, qqq 表示 draft, DeepMind 原文的字母约定与这里相反;

从 LM head 到 sampling distribution

先把模型输出和 sampling 分开看; 输入 tokens 经过 Transformer blocks, 得到当前位置的 hidden state hth_tht​, 然后 LM head 将它映射到 vocabulary 上的 logits;

x≤t→Transformerht→LM headzt∈R∣V∣→sampling policyp(⋅∣x≤t).x_{\le t} \xrightarrow{\mathrm{Transformer}}h_t \xrightarrow{\mathrm{LM\ head}}z_t\in\mathbb{R}^{|V|} \xrightarrow{\mathrm{sampling\ policy}}p(\cdot\mid x_{\le t}). x≤t​Transformer​ht​LM head​zt​∈R∣V∣sampling policy​p(⋅∣x≤t​).

Logits 还不是概率向量; temperature, softmax, top-k / top-p 等操作共同决定实际 sampling distribution; greedy decoding 也可以理解成把概率质量全部放在 argmax token 上;

因此手稿里的 zqz_qzq​ 和 zpz_pzp​ 是两组 logits, 真正进入接受公式的是经过各自 sampling policy 后的 qqq 和 ppp; 其中 qqq 必须是实际生成候选的 proposal distribution, ppp 是最终希望保持的 target distribution; 两者不要求使用相同的 policy, 但不能在 sampling 时用一套分布, 在接受比里又代入另一套;

从单个 token 接到一段 draft

小模型先自回归生成 γ\gammaγ 个候选, 大模型再对这些已经给定的候选位置做一次并行 forward; 每个位置仍然使用自己对应的 prefix, 并没有取消模型的因果依赖;

qi(⋅)=q(⋅∣prefix,x1,…,xi−1),pi(⋅)=p(⋅∣prefix,x1,…,xi−1).q_i(\cdot)=q(\cdot\mid\mathrm{prefix},x_1,\ldots,x_{i-1}),\qquad p_i(\cdot)=p(\cdot\mid\mathrm{prefix},x_1,\ldots,x_{i-1}). qi​(⋅)=q(⋅∣prefix,x1​,…,xi−1​),pi​(⋅)=p(⋅∣prefix,x1​,…,xi−1​).

随后按位置顺序判断接受情况; 在第一个拒绝的位置 jjj, 从 norm⁡([pj−qj]+)\operatorname{norm}([p_j-q_j]_+)norm([pj​−qj​]+​) 采样 correction, 并丢弃这条 draft 后面的候选; 如果全部接受, 还可以从已经算出的 pγ+1p_{\gamma+1}pγ+1​ 再采一个 bonus token;

因此一轮推进的是 连续接受的 draft tokens + 1 个 correction / bonus token; 每轮至少推进一个 token, 但这只减少 target 的串行调用次数, 不保证总时间一定更短, 因为 drafting 和 verification 本身都有成本;

SpecInfer: 提高一次验证的有效长度

手稿里对 SpecInfer 的关注点是: 单条 draft 只覆盖一条未来路径, 如果前面的某个 token 没匹配上, 后面做的工作就浪费了; 那么可以让候选包含多个分支, 提高一次 target forward 能走下去的长度;

这里用 tree 表示多个可能的 continuation, 既能共享前缀, 也能让 target 一次计算多条路径对应的条件分布; 手稿将核心指标记为 matching length per unit time; 进一步区分实际输出长度与单纯的匹配长度, 可以写成:

有效输出速率≈E[Noutput]E[Tdraft+Tverify+Tother].\text{有效输出速率}\approx \frac{\mathbb{E}[N_{\mathrm{output}}]} {\mathbb{E}[T_{\mathrm{draft}}+T_{\mathrm{verify}}+T_{\mathrm{other}}]}. 有效输出速率≈E[Tdraft​+Tverify​+Tother​]E[Noutput​]​.

分子要分清是 accepted draft length 还是包含 correction / bonus 的 output length; 分母也不能只看 target verification; 增加树的宽度, 未必能提高这个比值;

原论文 Figure 2: SpecInfer 的 tree-based speculation 与 verification, 上半部分组织小模型候选树, 下半部分由 target 并行验证; 对应手稿里的 Learning-based Speculator 和 Token Tree Verifier;

Learning-based Speculator: expansion 与 merge

手稿把困难分成两个: 有限成本下挑出值得猜的路径, 以及 如何验证一棵树; 前一个问题对应 Learning-based Speculator, 其中又有两种组织方式;

方式 手稿中的理解 具体操作
Expansion 一个 SSM 扩展多个候选 从同一个 small speculative model 的输出中构造多个 continuation
Merge 多个 SSM 并行生成后合并 合并相同前缀, 保留分歧处的不同分支

如果每一层都保留 bbb 个孩子, 深度为 ddd 的树可能增长到 ∑i=1dbi\sum_{i=1}^{d}b^i∑i=1d​bi 个节点; 因此手稿中写到的内存压力是合理的, 不能无限扩展;

SpecInfer 的 ASPLOS 版本使用 static expansion configuration 控制每层分支数; 手稿里的 ⟨1,1,3,1,1⟩\langle1,1,3,1,1\rangle⟨1,1,3,1,1⟩ 可以作为自己的示例: 前两步每个节点只留一个孩子, 第三步留三个, 后面沿各分支继续单路延伸; 论文给出的示例是 ⟨2,2,1⟩\langle2,2,1\rangle⟨2,2,1⟩;

对于 merge, 手稿还记了 collective boost-tuning: 先用 target 生成训练序列, 训练第一个 SSM; 再把它已经覆盖的训练样本移除, 让后续 SSM 学剩下较难匹配的部分; 这样多个小模型更可能提供互补的候选, 而不是重复猜同一条路径;

多个 SSM 可以并行运行, 但是否隐藏额外成本取决于硬件与部署; 模型参数更少, 也不意味着单 token latency 按参数量同比下降;

Token Tree Verifier: topology-aware causal mask

手稿中 tree attention 的核心是 每个节点只看自己的祖先路径; 将整棵树展平后, 不能直接使用普通下三角 mask, 否则不同分支会看见不属于自己上下文的 tokens;

以公共 prefix I like 为例:

树中节点 父节点 该节点 attention 可以看到的 token context
a: cats prefix I like cats
b: dogs prefix I like dogs
c: because a I like cats because
d: and a I like cats and
e: because b I like dogs because

这里 c 和 e 虽然是同一个 token, 但祖先不同, 所以是两个节点; mask 允许公共 prefix, 当前节点的祖先与自身, 屏蔽其他分支; position 也按路径深度对齐; 节点的 hidden state 给出其后一个 token 的分布, 验证某个孩子时读取对应父上下文的预测;

整个过程是 target 先对候选树做一次并行 forward, 再根据结果选择可提交的路径; 并不是某条路径失败以后, 才重新跑 target 检查另一条; 最终只保留实际接受路径上的 tokens 与有效 KV, 其他分支不进入真实上下文;

随机 sampling 下, tree attention 只负责高效得到条件分布, 还需要正确的 acceptance / correction; SpecInfer 的 multi-step speculative sampling 在拒绝一个候选后, 更新当前 residual distribution, 再检查后续候选, 不能让每个兄弟节点都独立对原始 ppp 重试; 接受比里的 qqq 也必须对应实际 proposal 过程, 不能随意给一个确定性 top-k 节点套原始 softmax 的 p/qp/qp/q; 对应 论文 Algorithm 2;

并行验证的 memory I/O 直觉

手稿的直觉是: decoding 经常受 memory I/O 限制, target 同时验证少量 tokens 时可以复用读取的 weight tiles, 提高 arithmetic intensity; 多验证几个位置的 latency 可能小于逐个位置单独调用 target 的总和;

这里需要把手稿的 “并发验证不存在计算卡顿” 收窄: 小树可能利用原先闲置的算力, 但 verification 不是免费的; 树越大, activation, KV, attention 与矩阵计算的成本越高; 原论文也观察到较大 batch 下扩树会增加 verification latency, 所以仍要看每单位时间推进多少 tokens;

手稿中的 4:1, 3~7:1 和旁边的速度数字没有清晰注明单位与配置, 这里不把它们写成通用结论; 能在 旧版作者 PDF 核对到的是特定实验中 SSM 的 per-token latency 改善约 3.7×3.7\times3.7×; 旧稿还讨论了 learned scheduler 与 matching length per unit time, 但 ASPLOS 版本采用静态扩树配置, 两个版本应分开;

Medusa: 从同一 hidden state 预测多个未来位置

手稿在 Medusa 这里重新画了 LM head: tokens 经过 Transformer 得到 hth_tht​, 原始 LM head 预测 xt+1x_{t+1}xt+1​; Medusa 在同一份 hth_tht​ 上增加多个轻量 heads, 分别预测更后面的 tokens;

每个 Medusa head 包含带 residual connection 的轻量变换, 再投影到 vocabulary; 用列向量约定可以写成:

qt(k)=softmax⁡(W2(k)[SiLU⁡(W1(k)ht)+ht]).q_t^{(k)}=\operatorname{softmax}\left( W_2^{(k)}\left[\operatorname{SiLU}(W_1^{(k)}h_t)+h_t\right] \right). qt(k)​=softmax(W2(k)​[SiLU(W1(k)​ht​)+ht​]).

从各位置候选拼成 tree

手稿里的 z1,z2,…z_1,z_2,\ldotsz1​,z2​,… 是不同 heads 的 logits; 从每个 head 取多个候选, 就可以将这些未来位置的组合组织成树; 比如第一个 Medusa head 保留 2 个 token, 第二个保留 3 个, 简单笛卡尔组合就得到 6 条 continuation;

实际可以预先选择部分组合, 控制树的大小, 不必展开全部组合; 验证时使用 topology-aware causal mask, 共享 prefix 的计算与 KV, 每条路径仍然只看自己的上下文; 这部分可以与前面 SpecInfer 的 tree attention 放在一起理解;

Medusa-1 与 typical acceptance

手稿记到 Medusa-1 冻结 base model, 只训练额外的 Medusa heads; Medusa-2 则联合训练 heads 与 backbone; 这是 训练时是否修改 target 参数 的区别, 不能据此判断 decoding 时是否保持原 sampling distribution;

手稿中 typical acceptance 的关键词是 probability threshold; 对某条候选路径上的 token, 论文使用:

p(xi∣x<i)>min⁡{ϵ,δexp⁡[−H(p(⋅∣x<i))]}.p(x_i\mid x_{<i})> \min\left\{\epsilon,\delta\exp\left[-H\bigl(p(\cdot\mid x_{<i})\bigr)\right]\right\}. p(xi​∣x<i​)>min{ϵ,δexp[−H(p(⋅∣x<i​))]}.

其中 HHH 是 entropy, ϵ\epsilonϵ 是固定阈值, δ\deltaδ 调节 entropy-dependent threshold; target 分布越分散, 可接受的概率阈值可能越低; 按规则选出最长的可接受前缀, 论文这套策略对第一个 token 使用 greedy 并直接接受;

Typical acceptance 不具有前面 min⁡(1,p/q)\min(1,p/q)min(1,p/q) 加 residual correction 的严格分布保持保证; 它在可接受的生成质量与加速之间做取舍; 因此需要区分 “base model 参数被冻结”, “greedy 输出是否一致”, “随机 sampling distribution 是否保持” 这三件事; 对应 Medusa Section 2.3.1;

另外, 两次独立 sampling 恰好抽到不同 token, 不代表标准 speculative sampling 必然拒绝; 对前面推导的接受规则, 当 p=qp=qp=q 时接受率就是 1;

EAGLE-1: Feature-level autoregression 与 shifted token

手稿到 EAGLE-1 的问题是: 能不能让一个很小的 drafter 复用 target 已经算好的 feature, 然后在 feature level 自回归地预测后续位置;

原论文 Figure 6: EAGLE-1 的 drafting pipeline, feature 与提前一位的 token embedding 拼接后输入 Autoregression Head, 预测的 feature 再经原始 LM head 生成后续候选; 下半部分对应多轮扩展得到的候选树;

为什么只给 feature 还不够

沿用手稿的 How can 例子; target 处理完 How can 后得到 feature f2f_2f2​; 它可以给出下一个 token 的分布, 但下一个 token 可能抽到 I, 也可能抽到其他词; 一旦选择不同 token, 后续真实 feature 也会不同;

因此只给 f2f_2f2​, 就要求 drafter 直接预测下一位置的 feature, 会遇到 sampling 带来的分支不确定性; EAGLE 将已经选定的下一 token 也告诉 drafter, 例如现在明确选择了 I, 再预测 How can I 对应的 feature;

这里 xix_ixi​ 是 token ID, E(xi)E(x_i)E(xi​) 是 embedding lookup; feature fif_ifi​ 则带有 prefix 的上下文信息; 原论文将 feature 描述为 second-to-top-layer output, 指 LM head 之前的 hidden representation, 不能直接理解成倒数第二个 Transformer block;

小 drafter 如何生成候选树

拼接后的维度为 2d2d2d, 先由 FC 投影回 ddd, 再由一个轻量 Transformer decoder layer 预测下一 feature; embedding 与 LM head 复用 target 参数; drafter 有自己的 attention 与 KV cache, target feature 是它的输入, 不等于直接复用 target 内部的 attention KV;

这也对应手稿中 Medusa 与 EAGLE 的区别: Medusa 的多个 heads 从同一份 feature 并行猜不同未来位置; EAGLE 则将 已经选定的 token 与 feature 对齐后继续自回归, 下一步候选会受到前面所选分支的影响;

EAGLE-1 使用预先设定的树形模板组织候选, 再让 target 通过 tree attention 一次验证, 配合 speculative sampling 的接受与 correction 保持 target 分布; 因上下文而动态分配树预算的设计属于后续 EAGLE-2, 不应混入这里的 EAGLE-1 架构;

将手稿里的三个架构放在一起

方法 候选从哪里来 手稿关注的核心机制 验证时要区分什么
经典 speculative decoding 独立小模型自回归生成单条 draft 接受概率与 residual correction 保留连续接受前缀, 拒绝处补采样
SpecInfer 一个或多个 SSM 扩展, 合并候选 有限树预算, prefix sharing, tree attention 并行算 target 与分布正确的路径选择是两个步骤
Medusa 同一 hidden state 上的多个未来位置 heads 并行预测多个位置, 组合候选树 Typical acceptance 与 exact sampling 的保证不同
EAGLE-1 Feature 与 shifted-token 驱动的小 drafter Feature-level autoregression, 显式告知已选分支 固定候选树加 target verification, 保留严格 sampling 规则

这里的阅读顺序不代表严格的继承关系; 可以始终分两条线看: 候选怎样生成, 以及 target 怎样并行计算并决定最终输出;
